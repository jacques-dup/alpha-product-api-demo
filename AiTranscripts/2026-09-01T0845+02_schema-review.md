The schema is a serious MyAlpha-informed catalogue. It does not yet match the product-definition paradigm or the Whatsapp Content Distribution projection in a few important places. Dossier unchanged.

1. Translation vs contextualization (paradigm clash)
You froze: contextualization = sibling products; translation (dubs/subs) = a separate factor on any product, including the main family edition.

The schema does something else:

product.content_language ⇒ one product = one language of copy (alpha-film-series-es as its own row).
asset.language_code + group_code + v_product_language ⇒ media languages hang off the same product.
There is no dub vs sub field. Spanish dub and Spanish subs look the same (language_code = es).
So copy-translation is modeled as another product, and video-translation is modeled as assets, and neither is the “factor on a product” you described. That can work, but it is a different story. You need one rule:

Either: language editions are always new product rows (then drop “translation as a factor”, and say dubs/subs are assets on that language edition),
Or: one product per contextualization, many languages via assets (then content_language cannot mean “the” product language unless it is only default copy).
Without that rule, seed and WCD lookup will mix both patterns.
